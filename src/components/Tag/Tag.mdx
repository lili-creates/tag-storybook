## 05 · Reglas del texto

- Una sola línea, sin saltos.
- El ancho siempre se ajusta al contenido (hug). Nunca fill.
- La tag no trunca ni recorta su contenido. Por eso el texto debe ser corto: una palabra o una frase breve, tanto en Label como en Text.
- Si no cabe en una línea, se reescribe. No se fuerza el componente.
- Si el mensaje necesita más espacio o explicación, la tag no es el componente adecuado.

## 06 · Cuándo se usa la tag

### ¿Tag o texto plano?

Usa texto plano por defecto. La tag se justifica cuando reconocer un estado, categoría o incidencia ayuda a interpretar, localizar o priorizar información de la operación. Ser un dato categórico no basta: debe aportar utilidad para la tarea.

### Ejemplos logísticos

- ENV-10482, transportista DHL, destino Madrid, 24 palés y fechas: texto plano por defecto.
- Retenido en aduana en una tabla de envíos: tag, porque el usuario necesita localizarlo entre cientos de filas.

### En tablas densas

- Revisa la columna o tabla completa, no solo una celda.
- Usa small si la tag está justificada y omite el icono si no aporta lectura.
- No conviertas cada metadato en tag ni decores cada valor rutinario.
- Preserva la comparación entre filas y evita que la tag rompa la densidad de datos.

### Ante solicitud de color por estética

- Pregúntate qué distinción o decisión operativa facilita.
- Si no existe, mantén texto plano.
- Neutral solo si la etiqueta ya está justificada.
- Nunca elijas info/success/warning/error para combinar con una paleta.
- Si se necesita nueva clasificación cromática funcional, coméntalo con el equipo antes de realizar ningún cambio. Una vez aprobado, documenta su significado y consistencia a nivel de sistema antes de añadir colores fuera de estas variantes.

## 07 · Cómo se usa la tag

### Configuración paso a paso

1. Elige status según el significado operativo, no por el color.
2. Elige size: small en tablas y listas densas, default en tarjetas y vistas de detalle.
3. Escribe Text (siempre visible) y, si hace falta, Label. Ambos cortos.
4. Decide Show label group y Show icon. Si el contexto ya identifica al objeto, oculta el grupo.
5. Comprueba que el ancho es hug y que cabe en una línea. Si no cabe, reescribe el texto.

### Combinaciones

- Completa: icono + Label + Text. Cuando la tag identifica al objeto y expresa su estado.
- Sin icono: Label + Text. Cuando el icono no aporta lectura, por ejemplo en tablas densas.
- Solo Text: Show label group en false. Cuando el contexto ya dice de qué se trata.

<Canvas of={TagStories.Combinaciones} />

### Redacción

- Escribe un Label concreto y un Text breve. Evita la jerga.
- Una palabra o una frase breve en cada uno. Si no cabe en una línea, se reescribe (ver Comportamiento del texto).
- Evita duplicar información entre Label y Text: si el Label dice “Estado del pedido”, el Text dice “Confirmado”, no “El pedido está confirmado”.
- Escribe el Text con el mismo criterio en todo el producto: mismo estado, mismas palabras.

### Informar, no actuar

La tag no es un botón ni un filtro.

No añadas cierre, chevron, selección ni interacción. Si necesitas una acción, usa un control dedicado.

## 08 · Criterios de estado

Una vez justificada la tag, elige el estado según el significado operativo:

| Estado | Vista | Criterio |
| --- | --- | --- |
| **info** | <Tag size="small" status="info" label="info" text="text" /> | Información de contexto o progreso. |
| **success** | <Tag size="small" status="success" label="success" text="text" /> | Resultado completado correctamente. |
| **warning** | <Tag size="small" status="warning" label="warning" text="text" /> | Situación que requiere atención. |
| **error** | <Tag size="small" status="error" label="error" text="text" /> | Fallo o resultado no completado. |
| **neutral** | <Tag size="small" status="neutral" label="neutral" text="text" /> | Clasificación sin valoración semántica. Usa neutral cuando el estado importa pero el color no debe añadir significado. |

### Ejemplos de estado

- Retenido en aduana → warning
- Entrega fallida → error
- En tránsito → info o texto plano según la tabla
- Entregado → success o texto plano según la tabla
- Refrigerado o Mercancía peligrosa → neutral si ayuda a manipulación o planificación; no confundas categoría con incidencia.

### Icono neutral vs. estados de señal

En neutral no hay valoración que transmitir: el icono deja de indicar severidad y pasa a identificar el objeto o el contexto (por ejemplo, un paquete para un pedido). Por eso se puede sustituir.

En los estados de señal, el icono comunica severidad y no se puede cambiar.

Usa siempre el mismo icono para el mismo objeto en todo el producto y elígelo del set de iconos del sistema.

## 09 · Accesibilidad

### No depender solo del color

El estado debe expresarse con Text.

Si el grupo Label + icono está oculto, Text sigue comprensible. Si el icono está oculto, el Text debe bastar para comprender. Cuando el icono está visible, es decorativo y el Text lleva el significado (en el componente, el icono lleva `aria-hidden="true"`).

### Contraste y lectura

El contraste está asegurado con las variables creadas.

El icono, al ser decorativo, no requiere umbral mínimo. Mantén el orden de lectura según los elementos visibles: con label group visible, el orden es Label, texto; cuando label group es false, el orden es solo texto.

### Sin truncado ni tooltip

El contenido completo está siempre visible y lo leen los lectores de pantalla tal cual. No añadas un tooltip para recuperar texto recortado: si el texto no cabe, se reescribe.

### Sin semántica de botón

No uses `role="button"`, `tabindex` ni cursor de acción. La tag es contenido informativo y no entra en el orden de tabulación. Si el estado cambia en vivo, anúncialo desde el contenedor con `role="status"` cuando sea necesario.
